Approved AGS setup#

Read-only discovery found the selected namespace and its default public game client. Device ID credentials, statistics, leaderboards, and the trusted server client are absent. The previous deployment's server credentials cannot be reused.

The proposed setup preserves this prototype's existing guest flow and its visible browser-data-loss warning. It does not implement account linking.

Create a confidential client named Football 11 Sites Trusted Replay, with a fresh random ID and secret, no audiences, the new Site as base/redirect URI, and these catalog-verified module permissions:

{
  "oauthClientType": "Confidential",
  "clientName": "Football 11 Sites Trusted Replay",
  "modulePermissions": [
    {
      "moduleId": "m_cloud_save",
      "selectedGroups": [
        { "groupId": "g_game_records", "selectedActions": [2] },
        { "groupId": "g_player_records", "selectedActions": [1, 2, 4] }
      ]
    },
    {
      "moduleId": "m_statistics",
      "selectedGroups": [
        { "groupId": "g_user_statistics_value", "selectedActions": [1, 2, 4] }
      ]
    }
  ]
}

Use the discovered ags iam clients create --namespace <selected namespace> --json @<ignored request file> command. Generate the secret only after approval; keep it in ignored local configuration and Sites secret storage.

Enable Device ID with the discovered ags iam platform-credentials create operation and minimal body {"RedirectUri":"http://127.0.0.1","IsActive":true}. Bootstrap the game's existing Game Record, two server-set Statistics, the v3 season leaderboard, and friend-room Session template from the repository contracts. Keep their identifiers and gameplay settings consistent with the connected implementation. Do not grant the runtime client configuration-write permissions.

Write the new deployment's configuration to a separate ignored environment file, preserving the earlier deployment's local configuration.

Browser persistence repair#

Browser inspection reproduced the earlier saving warning. Direct Cloud Save OPTIONS returns 405 without CORS headers, although Node identity/storage checks pass. Browser saves now use fixed GET/PUT /api/latest-run routes. The backend verifies IAM identity and namespace, derives the owner, targets only the latest run key, and forwards the player's token. Writes validate replay, force private metadata, and accept at most 128 KiB. This route does not use the confidential client to elevate player-written saves.

Seven focused tests cover token/namespace rejection, fixed-slot addressing, cross-owner/public-record rejection, malformed/oversized payloads, replay/private metadata, and the browser transport. They pass within the full 150-test suite. Changed-file formatting and lint pass, with existing warnings only. A targeted scan of 316 source/browser artifacts finds no configured confidential values or recognized credential patterns.

In the deployed browser, both games complete eleven selections, report Result saved, and restore the same guest and result after reload.
